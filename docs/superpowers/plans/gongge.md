# 宫格图片实施方案

## 目标

在现有图片能力中增加 `storyboard_grid` 输出。文本模型根据创作要求规划 2～50 个画面，图片来源按自身单图或组图能力完成生成，结果以一个有序集合保存。

## 配置

### 图片能力

```text
kind = image
output_type = storyboard_grid
```

### 图片来源服务

```text
image_output_mode = single | group
max_images_per_request = 0 | 2..50
```

`max_images_per_request` 是接口单次技术上限，不是用户生成张数。用户侧不增加张数参数。

## 执行流程

1. 标准能力请求进入 Energon Gateway。
2. 默认文本能力根据提示词和参考素材规划 2～50 个有序画面。
3. 本次运行锁定已经选择的图片来源。
4. `single` 来源逐张调用；`group` 来源按单次技术上限分批调用。
5. 每批继续走现有参数映射、来源账号、调用日志、成本和媒体归一化流程。
6. 成功图片与失败格合并为统一 `storyboard_grid` 结果。

画布、工具、智能体和工作流只发起标准能力请求，不分别实现规划或循环。

## 结果和资产

- 结果的 `frames` 保存每格标题、说明、提示词、状态、图片和错误。
- `images` 保存成功图片的稳定顺序，`image` 兼容现有首图预览。
- 顶层保存一个集合资产，集合内容为完整结果协议。
- 每格图片保存为集合内有序子资产。
- 修改集合时，已有子素材始终使用当前版本；外部替换图片会复制进集合。

## 前端

- 普通图片节点检测 `storyboard_grid` 后展示多图宫格。
- 画布节点按每页布局分页展示，节点详情和资产详情继续展示完整结果；三处复用 `StoryboardGridView`。
- 节点详情允许修改单格标题和说明。
- 单格“导入/替换图片”复用已有资产选择器。
- 详情布局桌面为三列，窄屏降为两列或一列。

## 下游

- 多文件参数读取集合内全部当前图片并保持顺序。
- 单文件参数收到集合时明确报错，要求选择具体图片。

## 手工验证

1. 配置一个 `single` 来源和一个 `group` 来源。
2. 运行相同宫格图片能力，确认两者返回相同协议。
3. 使用要求 12 张及更多张的提示词，检查规划数量、分批生成和集合内顺序正确。
4. 切换 2×2、3×2、3×3 每页布局，检查翻页和跨页替换索引正确。
5. 在节点详情替换一格并保存，重新打开仍显示当前版本。
6. 检查画布、工具、智能体、工作流及普通单图能力。

按照项目约束，本方案不由开发代理执行构建或测试命令。
