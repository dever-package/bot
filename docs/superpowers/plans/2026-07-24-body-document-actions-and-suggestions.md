# Body 文档操作与完成建议实施计划

## 目标

- 保留 `compose_document` 作为长内容文档的唯一生成入口，普通聊天行为不变。
- 右侧文档继续复用统一复制投影，并在 Body 工作台增加“保存到资产”。
- 保存右侧文档时只保存标题、有序正文块和文档内素材，不保存聊天引导语。
- 文档完整性交付后稳定展示自然语言收尾和可点击的后续建议。

## 设计

1. 在通用 Agent Chat 类型中增加可选的文档操作渲染器，由文档面板传入当前文档、消息 ID 和运行状态。通用组件不导入 Body 资产模块。
2. Body 对话页通过该插槽复用 `SaveAssetAction`。保存请求增加 `document_id`，服务端校验它属于当前已完成的助手消息。
3. 资产投影复用现有 Rich JSON 节点生成逻辑，并抽取文档节点构造函数。整条回复仍可保留引导语；显式文档保存排除引导语及文档外素材。
4. 文档完成审查通过后，如果审查未指定交互，则按文档交付策略要求 `present_suggestions`。普通聊天不应用该策略。
5. 强制展示建议的模型步骤不发布普通文本，避免工具调用前置语进入文档正文。
6. 前端从结构化输出读取 `message`，只在存在文档和建议时渲染为文档完成收尾，建议按钮沿用现有组件。

## 静态验证

- 对修改的 Go 文件执行 `gofmt`。
- 执行 Dever audit、JSON 解析检查（如涉及 JSON）和 `git diff --check`。
- 按项目要求不运行 build、type-check 或任何 test。
