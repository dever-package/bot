# 技能子系统收敛实施方案

## 目标

在不改变技能创建、安装、测试、发布和 runtime 调用能力的前提下，修复当前审查确认的正确性、安全性和性能问题，并删除已经失效的历史兼容路径。

## 实施顺序

1. Runtime 技能挂载
   - 元数据注入数量只限制提示词体积，不再限制实际可加载技能。
   - 增加技能搜索工具，保留所有已挂载技能的服务端索引。
   - 入口正文和后续文件读取共享整轮累计字符预算。

2. 技能草稿
   - 更新请求携带并校验期望版本，阻止陈旧页面覆盖新内容。
   - 内容版本只在草稿内容变化时递增，校验结果不再制造额外版本。
   - 保存只做结构校验；脚本语法校验放到测试和发布阶段。
   - 删除会猜测转义符和替换源码标点的启发式改写。

3. 技能配置
   - 所有非空密钥都参与输出脱敏。
   - 环境变量名禁止数字开头。
   - 删除只读不写的历史 skill_config_bind 兼容路径。

4. 技能安装
   - 使用数据库中的 pending 记录作为队列事实来源，支持进程重启后继续调度。
   - 通过数据库状态传播取消，避免仅当前进程可取消。
   - 安装规划器只接收任务数据，规则统一由内置智能体设定维护。

5. 前端收敛
   - 草稿提交和自动修复请求统一携带版本。
   - 删除前端重复维护的技能生成规则，只传递任务和真实上下文。
   - 复用已有通用数据判断和请求辅助逻辑，避免继续扩张单文件职责。

## 验证约束

按项目要求不执行 build、npm build 或任何自动测试。完成后只运行格式化、静态搜索、差异检查和逐路径代码复审，实际运行验证由用户手动完成。
