# 画布统一内容渲染设计

## 背景

画布目前按节点类型分别渲染文本、Markdown、富文本和媒体。能力节点的纯文本分支直接使用 `<p>`，功能结果卡片、结果气泡和资产节点又各自决定富文本或媒体的优先级，导致 Markdown 不解析、`rich_json` 与图文混排被降级、图片结果被 JSON 或单一媒体预览截断。

## 目标

- 所有画布节点使用同一套内容协议渲染语义。
- 普通字符串按 Markdown 渲染，支持 GFM 和换行。
- `rich_json` 按富文本节点顺序渲染，保留图文、视频、音频和文件混排。
- 纯媒体节点保留现有紧凑布局和尺寸自适应。
- 流式文本使用同一内容组件增量渲染，并保留自动滚动。
- 无法识别的结构才降级为 JSON。

## 组件边界

共享协议组件从 `EnergonContentView` 正式更名为 `ContentView`。`EnergonOutput` 和 `normalizeEnergonOutput` 继续保留协议名称，因为它们描述的是后端输出协议。旧导出名保留为别名，避免已编译插件在热更新期间失效；所有源码调用改用新名称。

画布新增 `CanvasNodeContentView`。它只负责：

1. 通过公开的 compat module 获取共享 `ContentView`。
2. 在输出为空时把 fallback 作为 Markdown 文本交给共享组件。
3. 透传 `streaming`、样式和媒体布局。
4. 在共享组件不可用时提供纯文本降级，不重复实现 Markdown 或 rich JSON 解析。

节点自身继续负责卡片尺寸、滚动容器、纯媒体尺寸回调和节点交互。协议解析不再散落在节点分支中。

## 数据流

`nodeContextOutput` 负责解包运行结果和旧富文本包装；`CanvasNodeContentView` 接收该规范化输出；共享 `ContentView` 使用 `normalizeEnergonOutput` 分派 Markdown、rich、媒体、进度、错误和 JSON 降级。

纯图片、视频、音频或文件且不含文本/rich 的结果继续使用现有节点媒体展示，以保留尺寸自适应。只要输出包含文本、rich 或多个内容块，就使用 `CanvasNodeContentView`，防止混排内容被首个媒体预览截断。

## 覆盖范围

- 能力节点正文和流式结果。
- 文本/资产节点正文与资产详情。
- 功能节点结果卡片。
- 智能体、流程等节点结果气泡。
- 节点详情中的只读内容展示。
- 共享组件的智能体结果、流式请求、团队调试、聊天消息和助理抽屉调用名称。

## 样式与交互

画布仍由卡片最外层滚动容器控制滚动条。统一内容组件只控制内容排版；标题、列表、引用、代码块、表格和富媒体按节点尺寸缩放。内容区域不添加 `nodrag`，节点拖动保持可用；交互媒体自身继续处理点击。

## 验证

按项目要求不运行 build 或自动测试。实施后进行源码调用面检查、旧导出残留检查和 diff 空白检查；由用户手动验证 Markdown、rich JSON、图文混排、纯图片和流式文本。
