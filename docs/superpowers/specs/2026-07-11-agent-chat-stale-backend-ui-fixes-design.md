# 智能体聊天流式与历史加载修复设计

## 背景

当前页面运行的是新前端，但主后端二进制早于本轮游标分页、消息持久化和 SSE 接口改动。由此产生三个表象：

- 历史消息接口没有使用最新的 `last_message_id` 逻辑，向上滚动会重复返回同一页。
- 智能体运行记录正常生成，但用户消息和助手消息没有写入 `bot_assistant_message`。
- 前端 SSE 连接不可用后回退到轮询，因此浏览器显示连续的 stream 请求。

数据库证据显示，`bot_agent_run` 在 13:42 仍有新记录，而 `bot_assistant_message` 最后记录停在 12:47；主后端二进制时间为 11:06，相关后端源码均在此之后修改。

## 修复范围

### 等待动画

- 等待圆点由 6px 缩小为 4px。
- 同步缩小间距和容器高度，保留原有三点动画节奏。

### 历史消息加载

- 删除消息区顶部的加载动画，避免空页探测时出现没有实际内容的加载提示。
- 保留 `olderMessagesLoadingRef` 请求锁，防止滚轮和 scroll 事件并发请求。
- 保持现有游标协议：每次使用当前最旧消息的 `last_message_id` 请求上一页；收到空数组后将当前会话标记为没有更早消息，不再请求。
- 不增加 `has_more`、总数查询或多取一条。

### 消息持久化与流式传输

- 不新增第二套保存逻辑，继续由 agent runtime 的 `BeginRunTurn` 和 `CompleteRunTurn` 统一写入消息。
- 不修改共享流协议。当前前端仍优先使用 SSE，SSE 异常时才回退轮询。
- 重启主 backend，使当前游标分页、消息持久化、状态恢复和 SSE handler 生效。
- 不重启 demo，不停止 Adminer。

## 验收标准

- 三点等待动画明显小于当前尺寸。
- 滚动到历史末尾后，空页只请求一次，之后继续上滚不再请求，也不显示顶部加载动画。
- 两个会话可同时运行，两个会话的用户消息和助手最终消息都保存在 `bot_assistant_message`。
- 正常环境下每个运行使用一条持续的 SSE 请求；只有 SSE 失败时才允许回退轮询。
- 关闭弹窗和切换会话不停止后台运行，显式停止只影响当前会话。

## 验证约束

按项目要求不运行测试或构建命令。实现后只做格式与静态差异检查，由用户在浏览器中手动验证运行行为。
