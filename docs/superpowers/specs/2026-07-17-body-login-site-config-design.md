# Body 登录页与站点配置设计

> 2026-07-21 更新：本文中“暂不接入飞书 OAuth”的范围约束仅适用于首期登录页交付；飞书登录已由 [Body 飞书登录实施计划](../plans/2026-07-21-body-feishu-login.md) 接续实现。

## 目标

恢复 Body 独立登录页，并让登录页与工作台使用一致的站点品牌配置。后台在“载体”下提供统一的“基础配置”入口，使用明确的数据表维护站点设置、登录页链接和第三方账号入口。

## 范围

- 恢复独立登录页，移除游客工作台和登录弹窗交互。
- 新增 Body 站点配置、登录页链接、第三方账号入口三个直接 Model。
- 新增一个后台“基础配置”入口，内部使用三个页签。
- 登录页和工作台共用同一份站点展示配置。
- 登录页预置“使用飞书账户继续”，本阶段不接入飞书 OAuth。
- 从后台菜单与权限入口移除原“画布”配置页。

## 非目标

- 不实现飞书授权、回调、用户绑定或 Token 签发。
- 不保存飞书 AppID、AppSecret 等无实际消费者的敏感配置。
- 不把工作台“项目 / 对话 / 工具 / 资产”改为数据驱动菜单。
- 不删除 `bot_body_canvas` 模型和表。项目创建仍通过它读取默认画布配置。
- 不使用数据模板维护这些配置。

## 数据模型

### `bot_body_config`

单例配置，固定使用 `id=1`，由 seed 保证默认记录存在。

字段：

- `id`：配置 ID。
- `site_name`：站点名称。
- `logo`：站点 Logo。
- `favicon`：浏览器 favicon。
- `login_title`：登录页标题。
- `login_description`：登录页说明。
- `created_at`：创建时间。
- `updated_at`：更新时间。

### `bot_body_link`

维护登录页顶部链接。默认没有 seed，空列表时登录页不显示链接导航。

字段：

- `id`：链接 ID。
- `name`：显示名称。
- `url`：链接地址。
- `target`：打开方式，限定为当前窗口或新窗口。
- `status`：启用或停用。
- `sort`：排序。
- `created_at`：创建时间。

### `bot_body_account`

维护登录页第三方账号入口，不承载实际 OAuth 凭据。

字段：

- `id`：账号入口 ID。
- `provider`：稳定标识，初始为 `feishu`，唯一索引。
- `name`：按钮名称。
- `icon`：按钮图标。
- `status`：启用或停用。
- `sort`：排序。
- `created_at`：创建时间。

默认 seed：

- `provider=feishu`
- `name=使用飞书账户继续`
- `status=启用`

## 后台页面

“载体”下只展示一个“基础配置”入口，页面内部包含三个页签：

1. 站点设置：单例 `set.json`，使用固定 `id=1` 保存 `bot_body_config` 记录。
2. 登录链接：标准列表和新增/编辑弹窗，直接使用 `bot_body_link` Model。
3. 三方账号：标准列表和新增/编辑弹窗，直接使用 `bot_body_account` Model。

后台 CRUD 只使用 Model + page JSON，不新增 CRUD Service 或 API。页签共享同一配置页面导航结构，避免在侧边栏产生三个平行入口。

原 `bot/body/canvas` 页面不再作为菜单和权限入口展示；模型与内部读取逻辑保留。

## 公开读取契约

新增公开只读接口：

```text
GET /bot/body/login/config
```

返回：

- `config`：站点名称、Logo、favicon、登录标题和登录说明。
- `links`：已启用且按 `sort,id` 排序的登录页链接。
- `accounts`：已启用且按 `sort,id` 排序的第三方账号入口。

该接口是登录页所需的聚合读取契约，不提供保存能力，也不返回任何敏感字段。Body 站点只公开这个精确路径，不放宽整个 `/bot/body/*` 权限。

前端使用共享的类型、规范化函数和缓存加载器读取该接口。登录页和工作台复用同一读取模块；请求失败时回退到 `dever.json` 的站点配置。

## 登录页

### 路由与认证

- `WorkLoginPage` 恢复为独立页面，不再渲染 `WorkHomeShell`。
- 未登录访问 Body 继续由现有 `access.mode=login` 跳转到 `/body/sign-in?redirect=...`。
- 账号密码登录和注册继续复用 `/user/auth/login`、`/user/auth/register`。
- 登录成功后按照 `redirect` 返回工作台。
- 删除工作台游客分支和 `WorkAuthDialog`，受保护页面不再维护第二套未登录状态。

### 页面布局

- 顶部：动态 Logo、站点名、可选的 `body_link` 导航和注册入口。
- 主区域左侧：飞书入口、分隔线、账号、密码、登录按钮和注册切换。
- 主区域右侧：使用登录页专属的大幅创作插画，与左侧标题和表单形成稳定的双栏版式。
- 视觉按确认后的目标图复刻页面比例、导航层级、公告条、背景纹理、留白和表单密度；站点品牌、登录文案和账号入口仍来自 Body 配置。

飞书入口本阶段只展示。点击后明确提示“飞书登录暂未开放”，不伪造授权跳转。

### 移动端

- 登录表单优先展示，保证首屏可以完成登录。
- 顶部链接收进菜单；没有链接时不展示菜单按钮。
- 右侧插画移动到表单下方并保持固定宽高比，不造成横向滚动。
- 表单、按钮、标题和长链接必须在窄屏内换行或截断，不与其他控件重叠。

### 站点品牌同步

共享配置加载后：

- 登录页和工作台显示相同的站点名与 Logo。
- 更新 `document.title`。
- 更新 favicon 链接。
- 配置缺失或接口失败时使用 `dever.json` 的默认站点名、Logo 和 favicon。

## 错误与安全边界

- 登录配置读取失败不阻断账号密码登录。
- 链接仅渲染已启用记录；无链接时不保留空导航区域。
- 外部链接使用新窗口时补充安全的 `rel` 属性。
- 后台负责 URL、provider 和必填文案的基础校验；前端展示层额外丢弃非 HTTP、HTTPS、mailto 协议的登录链接。
- 第三方账号表不存储密钥，未来接入 OAuth 时再设计凭据加密、回调校验和用户绑定。
- 不将 Body 站点改为 `access.mode=public`。

## 验收条件

- 未登录访问 Body 进入独立登录页，不出现工作台侧栏或游客工作台。
- 登录页品牌、文案、链接和第三方入口来自 Body 配置，接口失败时仍可登录。
- 飞书按钮存在且点击提示暂未开放。
- 登录成功正确返回 `redirect`。
- 后台“载体”只展示“基础配置”，内部三个页签均可维护对应直接表。
- 原“画布”管理入口不再展示，但项目创建与画布运行不因本次改动中断。
- 桌面和手机宽度下均无横向滚动、文字遮挡或控件重叠。

## 验证约束

按项目要求，不运行 `npm run build`、Dever build 或任何测试命令。实施阶段只做格式化、静态搜索、协议审查和改动自检，运行结果由用户手动验证。
