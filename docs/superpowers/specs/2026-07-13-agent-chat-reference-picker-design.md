# 智能体聊天引用选择器优化设计

## 目标

在不改变现有引用协议和后端接口的前提下，简化智能体聊天输入框的 `@` 选择器，并让消息内素材更容易识别、预览和引用。

## 范围

- 保留“当前会话”和“历史会话”两个入口。
- 删除“资源中心”入口及其前端加载逻辑。
- 会话和消息继续使用当前列表样式，不改成卡片。
- 消息下的已完成素材改为固定尺寸的横向缩略图列表。
- 优化引用项的悬浮预览，使正文和媒体居中展示。
- 不新增接口、数据表或第三方依赖。

## 选择器布局

- 桌面端宽度由当前约 720px 收窄到约 560px，移动端继续使用可用宽度。
- 搜索提示改为“搜索消息或会话”。
- 当前会话直接展示消息；历史会话先展示会话，进入会话后再展示消息。
- 同一轮中的智能体回复与用户消息合并为一行展示：智能体回复在左，用户消息在右。
- 左右两侧仍是两条独立消息，点击哪一侧只引用对应消息，不新增整轮引用协议。
- 同一轮内的素材统一展示在左右消息下方；点击素材只引用该素材。
- 移动端将用户消息和智能体回复改为上下排列，避免两列内容过窄。

## 素材展示

- 素材归属于对应消息，不再作为独立列表行展示。
- 只展示状态为已完成且存在可用地址的素材；生成中和失败素材不进入选择器。
- 素材使用约 88px × 88px 的固定缩略图，横向排列并自动换行，超出一行后进入下一行。
- 图片直接展示缩略图。
- 视频优先展示封面或首帧，并叠加播放图标。
- 音频和文件展示对应类型图标。
- 缩略图下只显示紧凑编号，例如“图1”“视频1”“音频1”“文件1”，不显示长文件名。
- 编号优先使用后端素材的 `display_no`，缺失时按同一消息内同类型素材顺序生成。

## 悬浮预览

- 继续复用现有 `ReferencePreviewPopover` 和懒加载预览接口。
- 预览正文在内容区水平居中，保留原始换行并限制最大宽度，避免长文本贴边。
- 单个图片、视频、音频或文件预览在内容区居中展示。
- 多个媒体使用居中的自适应网格；媒体保持比例，不拉伸填满弹窗。
- 输入框中的引用标签和已发送消息中的引用标签继续复用同一套预览组件。

## 数据与组件调整

- `ReferenceScope` 删除 `resource`。
- `ReferenceOption` 增加消息角色和消息级素材集合字段，由消息选项负责携带。
- bot 的引用加载器将消息和素材一次组装完成，删除资源中心的兼容模块读取。
- 选择器根据已加载消息的角色顺序派生轮次，不修改消息表，也不增加 `turn_id`。
- 分页加载旧消息后对当前全部选项重新分组；分页边界上的单侧消息在另一半加载后自动合并。
- 选择器拆分轮次行、消息侧和素材缩略图渲染，保持远程会话分页和消息分页逻辑不变。
- 素材类型、编号、预览地址的转换集中在引用加载器内，避免选择器重复判断业务数据。

## 状态与异常

- 会话和消息继续沿用现有加载、空状态和分页行为。
- 单个缩略图加载失败时展示对应类型图标，不影响其他引用项。
- 素材没有可用地址时不展示，避免产生无法预览或无法解析的引用。

## 验收要点

- `@` 弹窗只显示“当前会话”和“历史会话”。
- 同一轮的智能体回复在左、用户消息在右，左右两侧可以分别引用。
- 一轮内多个素材在消息下方从左到右排列，第五个及后续素材按可用宽度自动换行。
- 点击消息与点击素材产生不同引用类型。
- 图片、视频、音频和文件均使用短编号，不出现长文件名。
- 悬浮预览中的正文、图片和其他媒体均在内容区居中。
- 历史会话、消息分页、搜索和已有引用提交协议保持可用。

本次不执行构建或自动化测试，按项目约定由用户手动验证。
