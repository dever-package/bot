# 画布节点统一详情与版本编辑设计

## 背景

画布中所有可产出结果的节点都可以打开详情，但当前详情弹窗把资产加载、内容解析、富文本编辑、媒体预览、自动保存、版本切换和样式集中在 `space-page.tsx` 的单个组件中。界面使用接近全屏的编辑区和大卡片版本栏，信息层级不清晰；基础 CSS 与后置覆盖同时存在，导致尺寸、颜色和间距难以稳定维护。

当前实现还存在数据语义问题：点击历史版本会立即把它设为当前版本，随后自动保存可以直接修改历史记录；编辑保存会覆盖版本的创建时间；自动保存没有串行队列，关闭弹窗会清除尚未执行的保存；节点结果创建版本只有互斥锁，没有对同一运行结果做幂等复用。

## 目标

- 所有具有结果内容的节点共用一个详情弹窗外壳和版本交互。
- 左侧展示当前内容并允许手动编辑，支持 Markdown、rich JSON、图文混排、纯媒体、文件和 storyboard。
- 右侧展示紧凑的版本列表，历史版本只读预览，恢复历史内容时创建新版本。
- 手动编辑只更新当前工作版本，不因输入或自动保存新增版本。
- 每次节点成功生成最多创建一个版本，重复落库请求返回已有版本。
- 自动保存串行、可感知失败、关闭前不丢失修改。
- 版本列表按需分页，历史正文点击时再加载，避免版本增多后详情请求持续膨胀。
- 将详情功能从 `space-page.tsx` 拆出，内容协议、保存状态和版本 UI 各自保持单一职责。

## 非目标

- 不修改智能体、团队流程或能力的运行及 SSE 协议。
- 不把详情弹窗升级为独立资产管理页面。
- 不实现版本内容差异对比、版本删除、版本重命名或多人协同编辑。
- 不强制把所有输出转换成 Markdown，也不在编辑时暴露原始运行协议 JSON。

## 总体方案

采用共享外壳加内容适配器的组合方式：

```text
NodeDetailDialog
├── NodeDetailHeader
├── NodeDetailEditor
│   ├── RichContentEditor
│   ├── StoryboardDetailEditor
│   └── FileDetailEditor
└── VersionPanel
```

`NodeDetailDialog` 只负责弹窗布局、当前版本选择和关闭流程。`NodeDetailEditor` 根据已经规范化的资产内容选择编辑适配器。`VersionPanel` 只处理版本列表、分页和预览选择。自动保存由独立 hook 管理，不由视图状态 effect 隐式驱动。

## 界面设计

弹窗保持工作台式大视图，桌面端使用接近全屏的居中容器，外部保留 `12px` 到 `16px` 间距，最大圆角不超过 `6px`。整体为安静的白色编辑面，不使用渐变背景或大面积状态色。

```text
┌ 节点图标  节点名称  内容类型      保存状态       下载  关闭 ┐
├──────────────────────────────┬──────────────┤
│ 富文本工具栏                  │ 版本     15   │
├──────────────────────────────┤              │
│                              │ ● 第 15 版    │
│ 当前内容或历史预览            │   当前版本     │
│                              │   07:54       │
│ Markdown / rich JSON         │              │
│ 图文混排 / 媒体 / 分镜        │   第 14 版     │
│                              │   07:49       │
│                              │              │
│                              │   加载更多     │
└──────────────────────────────┴──────────────┘
```

### 顶部栏

- 左侧显示节点类型图标、节点名称和内容类型，不显示冗长说明。
- 保存状态只使用“未保存”“保存中”“已保存”“保存失败”四种短文本。
- 保存失败状态可点击重试；正常状态不使用彩色胶囊。
- 右侧仅保留内容相关操作，例如下载和关闭，图标使用现有 Lucide 图标并提供 tooltip。
- “最后更新”读取版本的 `updated_at`；没有该值时回退 `created_at`。

### 左侧内容区

- 工具栏吸附在内容区顶部，正文单独滚动。
- 编辑面为白色，正文区域保留稳定的阅读宽度和 `32px` 左右内边距。
- 纯文本和图文内容使用现有 `RichTextEditor`，继续支持 Markdown 与 rich JSON。
- 图片、视频和音频转换为富文本媒体块，在正文中直接显示真实媒体，可删除、替换、排序并补充文字。
- 文件使用附件块和可编辑说明，不显示原始 URL JSON。
- storyboard 使用现有分镜解析和 `StoryboardView` 编辑能力，在同一内容区展示可编辑行，不暴露原始 storyboard JSON。
- 智能体、流程和能力的运行协议只用于生成资产展示文档；详情编辑的是资产版本内容，不修改运行记录和工具事件。

### 右侧版本栏

- 桌面端固定宽度约 `304px`，与内容区之间使用一条分隔线，不使用大尺寸嵌套卡片。
- 每行显示版本号、时间、来源和一行内容摘要，当前版本使用小圆点和“当前”文本标记。
- 默认一次加载 `20` 条，底部使用“加载更多”，不一次渲染全部历史。
- 点击当前版本返回可编辑状态。
- 点击历史版本只加载并展示只读内容，不修改资产的 `version_id`。
- 查看历史版本时，左侧工具栏下显示轻量提示条：“正在查看第 N 版”，提供“返回当前版本”和“恢复为新版本”。
- 视口较窄时，版本栏改为右侧抽屉，不压缩正文到不可编辑宽度。

## 内容适配

新增统一的 `NodeDetailContentAdapter`，输入为资产 kind、版本 content 和节点 fallback，输出：

```ts
type NodeDetailEditableContent = {
  mode: "rich" | "storyboard" | "file";
  value: unknown;
  summary: string;
  downloadableUrl?: string;
};
```

适配器复用现有 `richDocument`、`normalizeEnergonOutput`、媒体提取和 storyboard 解析，不在详情组件内复制协议判断。优先使用资产版本中的展示文档；只有尚未创建资产时才读取节点的 `result_output` 或 description 作为 fallback。

保存时执行反向适配：富文本保存为规范 rich document 或 Markdown document；storyboard 保存为规范 storyboard JSON；附件和媒体保留结构化节点及原始顺序。无法识别的结构化内容使用只读 fallback，并显示明确错误，不直接把整段 JSON 当正文。

## 版本语义

版本分为当前工作版本和历史版本：

- 节点成功生成结果时，通过 `SaveVersion` 创建新的当前版本。
- 手动编辑通过 `UpdateVersionContent` 更新当前版本，不增加版本号。
- `UpdateVersionContent` 必须校验提交的版本就是资产当前 `version_id`，禁止修改历史版本。
- 历史版本永远只读，前端选择历史版本不调用切换接口。
- “恢复为新版本”复制选中版本的内容，调用专用恢复业务方法创建最新版本，并将它设为当前版本。
- 当前版本被后续生成或恢复替代后即成为历史版本，不再允许修改。
- 删除现有详情弹窗对 `use_asset_version` 的依赖；确认无其它消费者后移除危险的直接切换接口和 Service 方法。

版本来源继续存放在现有 `source` 中。生成版本记录运行和节点来源；恢复版本记录 `action: "restore"` 和 `restored_from_version_id`，不新增平行审计表。

## 自动保存状态机

新增 `useNodeDetailDraft`，复用现有画布自动保存中的 revision、in-flight 和 generation 思路，但不共享画布保存 API。

状态为：

```text
saved -> dirty -> saving -> saved
                    └──> error -> retry -> saving
```

规则如下：

- 正文发生真实变化后标记 `dirty`，停止输入 `1200ms` 后调度保存。
- 规范化后的内容与最近保存快照一致时不发送请求。
- 同一详情最多一个保存请求在途；保存期间的新输入只增加 revision，请求结束后仅提交最新快照。
- 旧请求响应不得覆盖比它更新的本地 revision。
- 保存失败后停止自动循环重试，只展示一次错误并允许用户点击重试。
- 切换到历史预览前先保存当前草稿；保存失败则保持当前版本，不进入历史预览。
- 关闭弹窗时，有 dirty 或 saving 状态则执行 flush；失败后询问继续编辑或放弃修改。
- 弹窗卸载和节点切换通过 generation 使旧响应失效。
- 保存状态不作为 debounce effect 的调度依赖，避免状态变化重复创建定时器。

## 后端数据与接口

### 版本时间

`bot_asset_version` 增加 `updated_at`：

- 创建版本时同时写入 `created_at` 和 `updated_at`。
- 手动编辑只更新 `content` 和 `updated_at`，不再修改 `created_at`。
- 旧记录没有有效 `updated_at` 时，响应层回退 `created_at`。

### 生成幂等

`SaveVersion` 在资产保存锁内，若 `request_id` 和 `node_key` 均非空，先按 `asset_id + request_id + node_key` 查找已有版本：

- 已存在时返回该版本并把资产 `version_id` 指向它，不重复插入。
- 不存在时才计算下一个版本号并插入。
- 空 `request_id` 的主动保存不参与该幂等键，避免不同人工操作被错误合并。

互斥锁继续负责并发串行，幂等查询负责重复业务请求；两者职责不同，不能只保留其中一个。

### 详情与历史读取

调整现有详情读取，不再返回所有版本的完整 content：

- `asset_detail` 返回资产、当前版本内容、首批轻量版本项、`version_total` 和 `has_more`。
- 版本列表项只包含 id、version、source、created_at、updated_at 和短摘要。
- 新增分页读取版本列表的薄 API，业务查询放在 asset/project Service。
- 新增按资产和版本读取单条历史正文的薄 API。
- 新增“恢复版本”业务 API，由 Service 校验项目归属、复制内容并调用现有版本保存流程。

历史加载失败时前端显示局部错误和重试按钮；不能像现有逻辑一样静默吞掉异常。

## 前端文件边界

新增目录：

```text
front/src/nodes/body-work/space/node-detail/
├── node-detail-dialog.tsx
├── node-detail-header.tsx
├── node-detail-editor.tsx
├── node-detail-content.ts
├── version-panel.tsx
└── use-node-detail-draft.ts
```

职责约束：

- `space-page.tsx` 只保存当前打开的节点并渲染 `NodeDetailDialog`，不保留详情内部状态。
- `node-detail-content.ts` 负责内容正反向适配和摘要，不发请求。
- `use-node-detail-draft.ts` 负责草稿、保存队列和关闭前 flush，不包含 JSX。
- `version-panel.tsx` 负责列表、选中和分页，不解释内容协议。
- 共享富文本、媒体和 storyboard 能力继续复用现有组件，不创建第二套渲染器。
- 详情样式集中在一个连续的 CSS 区域，删除旧规则和后置覆盖，不保留两套选择器。

## 数据流

打开详情：

```text
画布节点 -> asset_detail -> 当前版本 + 轻量历史列表
         -> 内容适配器 -> 当前编辑器
```

手动编辑：

```text
编辑器 onChange -> draft revision -> debounce
                -> update_asset_version -> 合并资产 -> 更新画布节点
```

历史预览与恢复：

```text
点击历史项 -> asset_version_detail -> 只读预览
恢复为新版本 -> restore_asset_version -> SaveVersion -> 新当前版本
```

节点再次生成：

```text
节点执行完成 -> SaveVersion(request_id + node_key)
             -> 已存在则复用 / 不存在则新增
             -> 更新当前版本和画布节点
```

## 错误处理

- 当前详情加载失败时保留弹窗外壳，显示错误和重试，不渲染空白编辑器。
- 历史正文加载失败只影响选中的历史预览，不清空当前草稿。
- 恢复失败不改变当前版本，也不提前把历史内容写入节点。
- 自动保存失败保留用户草稿和 dirty revision，不把失败内容标记为已保存。
- 内容解析失败时保留原始数据用于下载或只读查看，并记录明确错误；不静默替换为空内容。
- 快速选择多个历史版本时使用请求序号或 AbortController，只接受最后一次选择的响应。

## 实施顺序

### P0：数据正确性

- 当前版本更新校验和 `created_at`/`updated_at` 分离。
- 生成版本按运行请求幂等。
- 历史版本只读，恢复时复制为新版本。
- 自动保存串行、失败停止循环、关闭前 flush。

### P1：结构与界面

- 提取 `node-detail` 目录和共享内容适配器。
- 所有节点接入统一详情外壳。
- 重做顶部栏、编辑区和紧凑版本栏。
- 删除旧详情 CSS 和 `space-page.tsx` 内重复逻辑。

### P2：加载性能

- 版本摘要分页。
- 历史正文按需加载和请求取消。
- 对长版本列表和大媒体内容做稳定滚动与响应式版本抽屉。

## 验收标准

- 文本、能力、智能体、流程、展示、图片、视频、音频、文件和分镜结果都能打开同一套详情弹窗。
- Markdown、rich JSON 和图文混排按最终效果展示并可编辑，不显示协议 JSON。
- 媒体显示真实内容，分镜显示可编辑行。
- 只输入和自动保存不会增加版本数量。
- 同一节点运行结果重复落库不会新增第二个版本。
- 点击历史版本不改变当前版本，历史内容不可编辑。
- 恢复历史版本后产生一个新版本，原历史内容保持不变。
- 快速连续输入、切换版本和关闭弹窗不会丢失新内容，也不会被旧响应覆盖。
- 保存失败不会无限请求，用户草稿仍然保留。
- 版本创建时间不会因手动编辑改变，最后编辑时间单独更新。
- 首次打开详情不下载所有历史正文，版本列表可以继续分页。
- 详情功能不再集中在 `space-page.tsx`，内容解析、保存和版本列表没有重复实现。

## 验证约束

按项目要求不运行 build 或自动测试。实施完成后只执行静态引用检查、Dever 审计和 diff 空白检查；界面交互、生成幂等、自动保存和历史恢复由用户手动验证。
