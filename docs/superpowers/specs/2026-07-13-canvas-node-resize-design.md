# 画布矩形节点等比例缩放设计

## 背景

body 画布节点已经在 `SpaceCanvasNode` 中保存 `x`、`y`、`width` 和 `height`，画布保存协议及自动保存也会持久化这些字段，但目前用户只能拖动节点位置，不能调整内容节点的展示面积。文本容易出现过度滚动，图片和视频也无法按画布布局手动放大或缩小。

## 目标

- 允许用户从矩形内容节点的四个角等比例调整大小。
- 缩放时实时更新节点外观和连线位置。
- 缩放结束后复用现有画布状态及自动保存，不新增后端接口或数据字段。
- 缩放交互不影响节点拖动、内容滚动、连接手柄和节点内部操作。
- 保持智能体圆形、流程六边形和功能胶囊的固定视觉语义。

## 节点范围

允许缩放的节点：

- 文本、图片、视频、音频、文件及混合内容资产节点。
- 能力节点，包括生成前空状态、流式生成状态和生成结果状态。

保持固定尺寸的节点：

- 智能体节点。
- 团队流程节点。
- 开始、导入、保存、展示等功能节点及其结果卡片。

## 组件设计

新增一个画布私有的 `CanvasNodeResizer` 组件，统一封装 `@xyflow/react` 的四个 `NodeResizeControl`。组件只接收节点类型、选中状态和缩放结束回调，并负责：

1. 判断节点是否允许缩放。
2. 只在允许缩放且节点被选中时展示四个角的手柄。
3. 通过 `keepAspectRatio` 保持节点当前宽高比。
4. 统一设置最小尺寸和最大尺寸。
5. 阻止缩放手柄触发节点拖动或画布平移。

所有矩形节点复用同一个缩放组件，不在资产节点和能力节点的各个渲染分支中重复缩放逻辑。

## 尺寸约束

- 最小宽度为 140，最小高度为 100。
- 最大宽度和最大高度均为 720。
- 缩放始终以节点当前比例为准，不强制图片、视频或文本共享固定比例。
- 从左上、右上或左下角缩放时，同时保存 React Flow 计算后的 `x/y`，避免松手后节点位置跳回。

## 状态与持久化

缩放过程由 React Flow 维护临时尺寸和位置，让节点与连线实时更新。缩放结束时，`CanvasNodeResizer` 把最终的 `x`、`y`、`width`、`height` 交给画布层。画布层只更新目标 `SpaceCanvasNode`，随后调用已有 `onNodesCommit`。

`onNodesCommit` 继续进入当前 canvas state 更新、dirty 标记和 `useCanvasAutosave`，最终沿现有保存接口持久化。该功能不修改智能体运行、能力执行、流式协议或后端画布模型。

媒体节点现有的自然尺寸回调只负责结果首次展示时的建议尺寸。用户缩放结束后的尺寸是画布状态中的最终尺寸，后续普通重渲染不得覆盖；只有生成结果实际发生变化时才允许重新采用新媒体的建议尺寸。

## 样式与交互

- 四角使用低干扰的直角标记，位于节点边框外侧，不占用内容空间。
- 手柄仅在节点选中时出现；悬停时增强对比度。
- 手柄使用 `nodrag` 和 `nopan`，不会触发节点拖动或画布移动。
- 缩放期间节点内容继续裁切或滚动，不改变现有内容渲染组件。
- 连接手柄仍位于节点左右两侧，并跟随节点尺寸实时居中。

## 验证

按项目要求不运行 build 或自动测试。实施后只进行源码静态检查和 diff 空白检查，由用户手动验证：

- 四个角都能等比例缩放文本、图片、视频和能力节点。
- 从左侧两个角缩放时节点位置稳定，松手后不会跳动。
- 缩放时连线端点实时跟随。
- 松手后刷新页面，节点尺寸和位置仍然保留。
- 缩放手柄不影响节点拖动、正文滚动、媒体操作和左右连接手柄。
- 智能体、流程和功能节点不显示缩放手柄。
