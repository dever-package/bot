# 统一资产详情弹窗设计

## 目标

Body 资产列表与画布节点使用同一种详情弹窗结构，避免两套弹窗在布局、版本选择和预览规则上继续分化。

## 范围

- 资产列表点击卡片后，打开与画布节点详情一致的全屏详情界面。
- 资产详情内容只读，不提供文本、富文本、分镜或文件编辑能力。
- 保留资产现有的设置当前版本、使用、继续对话和重新生成操作。
- 画布节点详情现有的编辑、自动保存、历史版本恢复和视频合成功能保持不变。
- 桌面端和移动端共用同一套响应式弹窗结构。

## 组件边界

在 `front/src/nodes/body-work/shared` 中抽取共享详情组件：

1. `DetailDialogFrame` 负责 Portal、遮罩、全屏容器、关闭交互和可访问性属性。
2. `DetailDialogHeader` 负责类型图标、标题、副标题、状态、版本入口和操作区插槽。
3. `DetailVersionSelect` 负责版本下拉、当前版本标识、分页加载、错误和重试状态。

画布 `NodeDetailDialog` 与资产 `AssetDetailDialog` 继续分别负责数据请求和业务动作，只组合上述共享组件，不互相伪造业务上下文。

## 数据流

### 资产详情

1. `AssetBrowser` 传入 `teamID + assetID`。
2. `AssetDetailDialog` 继续调用 `workbench/asset_detail`、`asset_versions` 和 `asset_version`。
3. 版本数据规范化为共享版本选项，再交给 `DetailVersionSelect`。
4. 当前选择的版本交给只读预览区，按文本、图片、音频、视频、富文本和文件类型渲染。
5. 设置当前版本后刷新详情和资产列表；使用或继续操作仍回调给现有调用方。

### 画布节点详情

1. 保留项目资产接口、草稿状态、自动保存和版本恢复流程。
2. 仅将弹窗外框、头部和版本选择 UI 替换为共享组件。
3. 编辑器、分镜编辑、视频合成和未保存确认仍归画布节点详情所有。

## 交互规则

- 点击遮罩或关闭按钮关闭；画布存在未保存内容时仍走原有确认流程。
- 资产详情切换历史版本只改变预览，不自动改变当前版本。
- 非当前版本提供“设为当前”；当前版本按调用场景显示“使用”或“继续”操作。
- 图片和视频居中等比放大；音频使用宽播放器；文本、富文本和文件采用适合阅读的内容宽度，不强制居中。
- 加载、空数据、错误与重试状态统一显示在内容区域。

## 错误处理

- 详情加载失败时保留弹窗并显示重试入口。
- 单个历史版本加载失败不清空已加载的版本列表。
- 设置当前版本失败时保留当前预览和选择状态。
- 请求期间禁用重复提交操作。

## 验收标准

- 资产页和画布节点详情使用同一个共享弹窗框架、头部和版本选择器。
- 资产详情为只读，不触发画布项目编辑接口。
- 工具、对话、上传等非项目资产无需伪造 `projectID` 或节点。
- 资产原有版本和操作能力无回归。
- 画布节点详情的编辑与保存行为无变化。
- 无新增重复弹窗样式；共享样式只维护一份。
- 按项目要求只执行静态审计与差异检查，不运行构建或测试。
