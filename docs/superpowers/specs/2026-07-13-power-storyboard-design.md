# 能力分镜脚本类型与设定提示词设计

## 背景

能力已经通过 `Power.Kind` 区分文本、图片、视频、音频等类型，画布能力节点直接读取这个字段生成分类、标题和结果语义。因此脚本不应成为新的画布节点类型，也不需要新增平行的 `power_mode`；它应是现有能力类型的一个新值。

能力目前没有统一的设定提示词。画布只能提交本次输入，后台能力调试和其他调用入口也无法复用能力自身的长期指令。脚本能力还需要稳定输出 storyboard JSON，不能要求每个画布节点重复填写完整协议提示词。

## 目标

- 在现有能力类型中增加 `storyboard`，后台和画布显示为“分镜脚本”。
- 给能力增加默认空的设定提示词，并在所有 Energon 调用入口一致生效。
- 脚本能力自动叠加固定的 storyboard JSON 协议提示词。
- 继续复用现有能力节点、SSE、上下文、参数和连线执行路径。
- 为后续可编辑分镜表格提供稳定的结构化结果协议。

## 数据模型与后台配置

`model/energon.Power` 增加 `Prompt string`，数据库字段为 `prompt`，类型为 `text`，非空且默认空字符串，后台名称为“设定提示词”。能力编辑页增加编辑器字段，允许所有能力填写长期设定；留空时不产生额外指令。该字段放在能力编辑表单最后，避免打断来源和参数配置流程。

现有 `kindOptions` 增加：

```json
{"id": "storyboard", "value": "分镜脚本"}
```

画布目录继续从能力列表读取 `kind`。前端只补充 `storyboard` 的中文标签和图标映射，不增加新的 `SpaceNodeType`。

## 提示词合并

设定提示词在 Energon 选中能力后统一注入请求的 `set.role`，不在画布或后台调试入口分别拼接。合并顺序固定为：

1. `storyboard` 类型的内置协议提示词。
2. 能力管理员填写的设定提示词。
3. 调用方原有的 `set.role`。

空内容会被忽略，各段之间使用空行分隔。普通能力不会加入脚本协议，只使用能力设定和调用方设定。统一注入可以保证后台测试能力、画布能力以及其他 Energon 调用入口行为一致，同时避免把系统设定混入用户输入。

## Storyboard 协议

脚本能力的内置提示词要求模型只返回一个 JSON 对象，不附加 Markdown 代码围栏或解释文字。第一版协议为：

```json
{
  "type": "storyboard",
  "version": 1,
  "title": "故事标题",
  "shots": [
    {
      "id": "shot-1",
      "order": 1,
      "duration": 4,
      "visual": "画面描述",
      "dialogue": "台词",
      "narration": "旁白"
    }
  ]
}
```

`duration` 使用秒，必须为正数；`shots` 保持生成顺序；没有台词或旁白时对应字段使用空字符串。模型输入可以是文本、图片、视频或上游混合结果，媒体继续通过现有上下文协议传递。

## 执行与结果

分镜脚本属于能力的媒体任务类型，仍按 `power` 节点执行，沿用当前 SSE 传输和上下文合并。SSE 中的原始文本增量继续在运行状态中累积，但画布不把未完成的 storyboard JSON 当普通文本渲染。能力类型只控制设定和结果语义，不产生暂停、审批或特殊流程行为，也不强制改写现有媒体适配器的类型选择。

共享画布结果层负责 storyboard 协议识别与可编辑表格；解析成功时展示分镜行，分镜能力解析失败时显示格式异常状态，其他内容类型继续使用现有 `ContentView`。展示异常不改变执行结果，编辑后的标准 JSON 继续作为节点结果传给后续节点。

## 画布来源选择

画布继续使用能力表单已有的 `source_rule`、`selected_target_id` 和 `sources`，不新增接口或前端规则副本：

- `source_rule = 1` 时隐藏来源菜单，清理节点草稿里遗留的来源 ID，运行时提交 `selected_target_id = 0`，由后端按排序使用第一个可用来源并负责失败重试。
- `source_rule = 2` 时展示来源菜单，并沿用当前按来源重新加载参数的逻辑。

这样管理员从“可以选择来源”改回“仅调用第一个来源”后，旧画布草稿也不会继续指定过期来源。

## 分镜结果视图与编辑

分镜解析放在共享的 `CanvasNodeContentView` 前置层，不在能力节点、资产节点和结果气泡里分别复制协议判断。解析器接受直接 JSON、JSON 字符串、Markdown JSON 代码块、Energon 包装字段以及资产版本中的富文本 JSON。普通内容调用方只有识别成功时才切换到分镜视图，否则继续使用现有 `ContentView`；已知为分镜类型的能力节点则由专用状态组件把最终解析失败展示为格式异常，不走普通文本降级。

分镜视图使用紧凑表格展示标题和镜头行。每行提供序号、时长、画面描述、台词、旁白和删除操作；时长可用加减按钮调整，镜头可上下移动，也可新增。输入控件阻止画布拖动事件，表格空白区仍保持节点可拖动，内容超出节点时在内部滚动。

脚本能力节点在生成完成后允许直接编辑。编辑先更新本地视图，停止输入 800 毫秒后调用现有资产版本更新接口；保存成功后用返回的资产版本更新节点结果和资产列表，使后续连线读取最新 JSON。没有稳定资产版本时只更新节点 `resultOutput`，交给现有画布自动保存。保存失败保留草稿并显示紧凑状态，不丢失输入。

### 画布节点状态

分镜能力使用专用的画布结果组件，不在通用能力节点分支中重复解析协议。组件只负责分镜的四种展示状态，表格编辑继续复用 `StoryboardView`：

1. 未生成：保留简洁空态，不展示协议或 JSON 示例。
2. 生成中：展示三行骨架、边框运行效果和“正在生成分镜，请稍候”。原始 JSON 增量只保存在运行状态中，不进入 `ContentView`，也不伪造“资产设计”等后端没有提供的阶段。
3. 已完成：顶部显示完成标记、标题、镜头数和总时长；中间展示可直接编辑的分镜表格，超出可视区域时内部滚动；底部提供“打开完整分镜”，复用现有节点详情入口。
4. 失败或格式异常：显示简短错误和重新生成提示。原始结果仍保留在节点结果中，可从详情查看，避免因为隐藏 JSON 而丢失诊断信息。

生成完成后才把最终输出交给 storyboard 解析器。解析成功时从运行态一次切换为结构化表格；解析失败时进入格式异常状态，而不是在小节点里铺开原始 JSON。

### 默认尺寸与旧画布

新建分镜能力节点默认使用 `620 × 360`，该宽度可以容纳当前最小宽度为 560px 的分镜表格，并继续支持现有四角等比例缩放。节点本体负责纵向裁切和内部滚动，不随镜头数量无限增高。

旧画布中仍为普通能力历史默认值 `180 × 180` 的分镜节点，在加载归一化时一次提升为 `620 × 360`。只匹配这一组精确历史默认值；其他尺寸视为用户主动调整并原样保留。迁移后的尺寸通过现有画布自动保存持久化，不新增迁移接口或数据字段。

### 组件边界

- `space-storyboard.ts`：保留协议识别、标准化、摘要和总时长等纯数据函数。
- `space-storyboard-view.tsx`：继续负责可复用的分镜表格与行编辑，不感知画布运行状态。
- 新的分镜节点结果组件：组合空态、骨架态、完成摘要、表格和格式错误态。
- `space-page.tsx`：只判断当前能力是否为 `storyboard` 并传入运行状态、最终输出和详情回调；普通文本、图片、视频能力继续走原路径。
- `space-model.ts`：集中处理新节点默认尺寸和精确的旧尺寸归一化，避免在渲染层临时改尺寸。

## 兼容与错误处理

- 旧能力的 `prompt` 默认为空，行为不变。
- 旧画布仍保存 `type: power` 和原有能力引用；仅精确匹配 `180 × 180` 的分镜节点做尺寸归一化。
- 未识别的能力类型继续按当前文本结果处理。
- 脚本模型没有严格返回 JSON 时，Energon 调用本身不因展示协议失败而失败；画布显示格式异常状态，详情保留原始结果供查看和修正。
- 不新增 Service、API、数据表或画布执行分支。

## 验证

按项目要求不运行 build 或自动测试。实现后只做源码引用检查、格式检查、Dever 静态审计和 diff 检查，由用户手动验证：

- 能力后台可选择“分镜脚本”并保存设定提示词。
- 普通能力留空设定时行为不变，填写后后台调试与画布调用都能收到设定。
- 脚本能力无需用户重复填写协议即可生成 storyboard JSON。
- 画布仍把脚本能力作为普通能力节点执行，SSE、连线和上下文保持正常。
- 生成期间只显示骨架和真实运行状态，不出现原始 JSON；完成后切换为可编辑表格。
- 新分镜节点为 `620 × 360`；旧的 `180 × 180` 分镜节点自动采用新默认尺寸，其他自定义尺寸不变。
- 多镜头表格在节点内滚动，节点详情仍能打开完整分镜。
