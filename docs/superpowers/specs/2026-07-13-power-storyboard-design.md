# 能力分镜脚本类型与设定提示词设计

## 背景

能力已经通过 `Power.Kind` 区分文本、图片、视频、音频等类型，画布能力节点直接读取这个字段生成分类、标题和结果语义。因此脚本不应成为新的画布节点类型，也不需要新增平行的 `power_mode`；它应是现有能力类型的一个新值。

能力目前没有统一的设定提示词。画布只能提交本次输入，后台能力调试和其他调用入口也无法复用能力自身的长期指令。脚本能力还需要稳定输出 storyboard JSON，不能要求每个画布节点重复填写完整协议提示词。

## 目标

- 在现有能力类型中增加 `storyboard`，后台和画布显示为“分镜脚本”。
- 给能力增加默认空的设定提示词，并在所有 Energon 调用入口一致生效。
- 脚本能力自动叠加固定的 storyboard JSON 协议提示词。
- 继续复用现有能力节点、SSE、上下文、参数和连线执行路径。
- 为后续可编辑分镜表格提供稳定的结构化结果协议。

## 数据模型与后台配置

`model/energon.Power` 增加 `Prompt string`，数据库字段为 `prompt`，类型为 `text`，非空且默认空字符串，后台名称为“设定提示词”。能力编辑页增加编辑器字段，允许所有能力填写长期设定；留空时不产生额外指令。

现有 `kindOptions` 增加：

```json
{"id": "storyboard", "value": "分镜脚本"}
```

画布目录继续从能力列表读取 `kind`。前端只补充 `storyboard` 的中文标签和图标映射，不增加新的 `SpaceNodeType`。

## 提示词合并

设定提示词在 Energon 选中能力后统一注入请求的 `set.role`，不在画布或后台调试入口分别拼接。合并顺序固定为：

1. `storyboard` 类型的内置协议提示词。
2. 能力管理员填写的设定提示词。
3. 调用方原有的 `set.role`。

空内容会被忽略，各段之间使用空行分隔。普通能力不会加入脚本协议，只使用能力设定和调用方设定。统一注入可以保证后台测试能力、画布能力以及其他 Energon 调用入口行为一致，同时避免把系统设定混入用户输入。

## Storyboard 协议

脚本能力的内置提示词要求模型只返回一个 JSON 对象，不附加 Markdown 代码围栏或解释文字。第一版协议为：

```json
{
  "type": "storyboard",
  "version": 1,
  "title": "故事标题",
  "shots": [
    {
      "id": "shot-1",
      "order": 1,
      "duration": 4,
      "visual": "画面描述",
      "dialogue": "台词",
      "narration": "旁白"
    }
  ]
}
```

`duration` 使用秒，必须为正数；`shots` 保持生成顺序；没有台词或旁白时对应字段使用空字符串。模型输入可以是文本、图片、视频或上游混合结果，媒体继续通过现有上下文协议传递。

## 执行与结果

分镜脚本属于能力的媒体任务类型，仍按 `power` 节点执行，沿用当前 SSE 流式输出和上下文合并。能力类型只控制设定和结果语义，不产生暂停、审批或特殊流程行为，也不强制改写现有媒体适配器的类型选择。

这一阶段先完成能力类型、设定字段和统一提示词注入。随后在共享画布结果渲染层增加 storyboard 解析器与可编辑表格；解析成功时展示分镜行，解析失败时降级为现有 `ContentView`，不阻断执行。编辑后的标准 JSON 继续作为节点结果传给后续节点。

## 兼容与错误处理

- 旧能力的 `prompt` 默认为空，行为不变。
- 旧画布仍保存 `type: power` 和原有能力引用，无需迁移。
- 未识别的能力类型继续按当前文本结果处理。
- 脚本模型没有严格返回 JSON 时，结果视图负责容错解析或降级展示；Energon 调用本身不因展示协议失败而失败。
- 不新增 Service、API、数据表或画布执行分支。

## 验证

按项目要求不运行 build 或自动测试。实现后只做源码引用检查、格式检查、Dever 静态审计和 diff 检查，由用户手动验证：

- 能力后台可选择“分镜脚本”并保存设定提示词。
- 普通能力留空设定时行为不变，填写后后台调试与画布调用都能收到设定。
- 脚本能力无需用户重复填写协议即可生成 storyboard JSON。
- 画布仍把脚本能力作为普通能力节点执行，SSE、连线和上下文保持正常。
