# Ask User 分步交互设计

## 目标

将单智能体运行时的 `ask_user` 从一次展示全部字段的大表单，调整为自然语言引导后的单题分步交互。交互协议和 UI 组件保持通用，可复用于智能体聊天、团队、工作流和后台 AI 助理。

## 范围

- 模型在调用 `ask_user` 前流式输出简短的自然语言说明。
- 一次 `ask_user` 携带 1-4 个必要问题，前端一次只展示一个问题；多个问题时显示步骤进度。
- 选择题使用卡片式单选或多选，支持 AI 推荐、默认选中、自定义补充和剩余问题交给 AI 决定。
- 最后一步统一提交结构化 `interaction_response`。
- 结构化回答写入消息，并进入当前请求及后续历史上下文。

第一版不修改知识库、技能、素材工具及 agent loop 的其他行为，不增加渠道专用判断，不兼容旧版表单协议。

## 运行时行为

1. 模型判断任务缺少必要参数。
2. 模型先输出一到两句自然引导，说明需要确认的信息及其用途，不在正文中列出完整问题。
3. 模型在同一轮调用 `ask_user`。
4. `ask_user` 作为终止型交互工具结束当前 run，并持久化 `interaction` 输出。
5. 用户完成所有步骤后，前端创建新的会话消息并提交 `interaction_response`。
6. runtime 将结构化回答交给模型；信息足够时继续任务，仍不足时再发起下一组问题。

模型未输出自然引导时，runtime 使用通用兜底文案：`为了继续完成这个任务，我需要先确认几个关键信息。`

## 工具协议

`ask_user` 不再要求模型生成可见标题或 UI 布局，只描述问题和选项：

```json
{
  "fields": [
    {
      "key": "ratio",
      "label": "图片比例",
      "type": "option",
      "options": ["1:1 方图", "3:4 竖图", "9:16 竖图"],
      "recommended": ["3:4 竖图"]
    }
  ]
}
```

约束：

- 每次 1-4 个字段，只询问无法安全推断的必要信息。
- 支持 `option`、`multi_option`、`input`、`textarea`、`number`、`switch`、`file`、`files`。
- `option` 和 `multi_option` 使用 2-6 个简短字符串选项。
- `recommended` 始终为字符串数组；单选取第一项，多选可取多项。
- 推荐值必须存在于 `options` 中，否则后端忽略无效推荐。
- 选项超过 6 个或无法合理枚举时使用自由输入类型。
- 后端统一补充字段必填、排序以及前端需要的 `{label, value}` 选项结构。

## 前端交互

通用 `AgentInteractionPanel` 增加 `stepper` 展示模式，`agent-chat` 只负责选择该模式，不复制表单状态和校验逻辑。

卡片结构：

- 卡片外仅保留模型的自然语言说明。
- 卡片顶部显示小型“需求确认”标识。
- 右上角显示 `Step 1/3` 和分段进度条。
- 中间一次展示一个问题。
- 单选、多选使用整行选择卡片，推荐项显示“推荐”标签并默认选中。
- 用户选择其他项后，推荐标签保留，选中状态随用户选择变化。
- 每个选择题固定提供“自定义补充”，选中后展开输入框并使用自定义值。
- 底部提供“上一步”“下一步”；最后一步为“提交并继续”。
- 底部提供“剩余全部交给 AI 决定”。只有剩余问题都有有效推荐值时才可用，点击后采用推荐值并直接提交。
- 已提交交互进入只读状态，显示每个问题的最终回答。

移动端保持单列，步骤按钮固定在卡片底部，问题内容区域独立滚动。

## 数据持久化与上下文

用户提交后，消息 `content` 保存：

```json
{
  "version": 1,
  "parts": [{"type": "text", "text": "图片比例：3:4 竖图"}],
  "interaction_response": {
    "interaction_id": "ask-user-...",
    "data": {"ratio": "3:4 竖图"}
  }
}
```

- `parts.text` 用于聊天区展示和人工阅读。
- `interaction_response.data` 是模型继续执行的权威数据。
- 当前 run 直接把结构化数据放入模型输入。
- 后续 run 的历史上下文也必须从消息 `content` 恢复结构化回答，不能只依赖摘要文本。
- 切换会话、关闭弹窗或刷新后，交互及已提交回答都从持久化消息恢复。

## 错误处理

- Function Calling 参数不是完整 JSON：返回明确的工具错误，要求模型缩短字段和选项后重新调用，不展示损坏表单。
- 字段超过 4 个：拒绝执行并要求模型拆成下一组。
- 选择题缺少足够选项：拒绝该工具调用。
- 推荐值无效：忽略推荐；如果剩余题存在无推荐项，禁用“全部交给 AI 决定”。
- 用户提交期间禁止重复提交。
- 提交失败保留当前步骤和值，显示错误后允许重试。

## 验收标准

- `ask_user` 前能看到连续的自然语言流式输出。
- 卡片不重复显示任务标题。
- 多个问题按步骤逐个展示，进度与前后切换正确。
- 推荐项有标签并默认选中。
- 自定义补充可以覆盖选项值。
- “剩余全部交给 AI 决定”只在所有剩余题都有推荐值时可用。
- 最后一步只提交一次，刷新后仍能看到只读答案。
- 模型在当前轮和后续轮都能读取结构化回答，不再声称未收到表单内容。
- 桌面端和移动端均无内容遮挡或按钮溢出。

按项目要求不运行 build 或自动化测试，由用户手动完成界面与运行链路验证；实施过程中只执行格式化、类型相关静态检查和 Dever 静态审计。
